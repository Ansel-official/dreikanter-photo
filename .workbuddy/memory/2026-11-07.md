## Dreikanter photo（图像编辑器，纯前端单页应用）
- 位置：工作区根目录，入口 `index.html`，可直接 file:// 打开（全部为经典 script，无模块/无构建）。
- 结构：`css/base.css`（PS 模式）、`css/apsis.css`（Apsis 覆盖）、`js/{util,icons,engine,filters,tools,ui,dialogs,apsis,agent,api,main}.js`。
- 引擎：全尺寸图层 canvas + 逐层混合模式合成；选区蒙版生成两条 Path2D（逐行矩形用于 fill/clip，像素边线段用于蚂蚁线）；History 采用「按图层差分快照 + 恢复时克隆画布」。

- API：`window.Dreikanter`（adjust/filter/style/text/shape/layer/transform/export/agent），控制台用 `new Function` 运行。
- 关键坑：顶层 const 不挂 window，跨文件回调需 `typeof X !== 'undefined'`；大面积 backdrop-filter 在无 GPU 环境会整屏模糊，已全部移除。

### 第三轮收尾的关键判断与坑
- **测试虚高**：原 173 条里有 46 条是逐字复制的填充断言（同一段 t(...) 重复 2–3 份），既污染文档状态又让「≥150 项」失真。写了括号配平扫描器去重 → 127 条唯一，再补 35 条真断言到 162。教训：要「项数」时不要复制粘贴，补新维度（键盘/API/Worker/工程卫生）。
- **假绿灯**：`return '未注册'`、`return '增长 30%'`、`x || true`、`Document ? true : true` 这类写法都会被 harness 当通过（返回字符串=pass）。统一约定：失败必须 `throw new Error(...)`，字符串只做 info。

- **性能断言抗抖动**：4K 滤镜预览在负载高的机器上 93→179ms 波动，改「3 帧中位数 + 200ms 预算」；首屏改用应用自身 `Perf.boot` 打点（`main.js` 初始化结束时写），运行器先预热一次导航，得到热启动 111ms 的稳定值（冷盘仍 700–1100ms，README 里两个数都写清楚）。
- **标尺专业化**：原来标尺贴画布（平移时整条标尺跟着跑）。改成钉在 `#stage` 左上角：`Guides.layout(0,0,stageW,stageH,dpr)`，竖向标尺从 y=20 起要减 20 偏移算 origin，补 `#rulerCorner` 角块，`window.innerWidth<=820` 自动隐藏把 20px 还给画布。
